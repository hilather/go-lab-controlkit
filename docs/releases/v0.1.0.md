# go-lab-controlkit v0.1.0

Tag: `v0.1.0` (Helm pushes it after the v0.1.0 changelog-fold PR merges)
Module: `github.com/hilather/go-lab-controlkit`
Go: `go 1.26` in `go.mod` (no `toolchain` line); CI builds and runs
`govulncheck` on Go 1.26.9
Dependencies: standard library only (`go.mod` has no `require` entries)
Previous release: none (first tag)

## Highlights

First tag of the shared management-plane kit for the go-lab repos. It
holds, in one place, the code that ntp, netconf, snmp, maildev, syslog and
dns each carry today: management token loading and verification, scope and capability
checks, sessions, Origin and CSRF checks, audit, idempotency, rate limiting
and strict MCP argument checks. Each consumer keeps thin facades in its own
packages, its own request flow and its own wire codes.

No consumer pins controlkit yet. Each consumer adopts `v0.1.0` in its own
PR-1 (adopt, no behavior change); the README consumer pin matrix records
the tag each consumer's `main` pins.

## Packages

- `kerr`: error kinds a facade maps onto its own wire code.
- `authn`: token loading, verifier, stdio pin, secret wiping, and reload.
- `scope`: principal table and capability gate.
- `session`: session table, CSRF compare, cookie helpers, and revocation
  wake.
- `origin`: Origin allow-list policy.
- `audit`: bounded ring, fanout, redaction, and the denial flood guard.
- `idem`: bounded LRU and FIFO idempotency cache.
- `ratelimit`: capped per-key buckets and a per-call global bucket.
- `mcpstrict`: duplicate JSON keys, typed subtrees, and open fields. Check's
  allocation measured linear on every pinned shape; per-shape bounds are
  enforced by tests (see CHANGELOG).
- `kittest`: conformance suites that take injected drivers, including
  `DuplicateKeyNoEffect` and the `ResetZeroTokens` shapes.

## Behavior notes for consumers

- No constructor invents a default. A zero value in a config struct is a
  constructor error unless the field's comment names what zero means.
- Per-repo options that differ today (`authn.FileOpts.TrimRef`,
  `authn.Config.RejectBlankTokens`, `origin.Policy.ZonedLoopback`,
  `authn.MinSecretBytes` and the others) are listed in the README option
  ledger with the value each consumer sets. A facade must set each one to
  match its repo's current behavior.
- The kit's bad-token text is `invalid token`; facades map it to their own
  text and wire code.

## Compatibility

- v0: a minor release may break the API. At most one API-breaking minor is
  in flight at a time. `apidiff` becomes a required check from `v1.0.0`.
- Tags are never moved or deleted. A bad release gets a `retract`
  directive and a new patch tag.
- `kittest.ManagementRebindOverAPI` and `kittest.RebindVariant` are marked
  EXPERIMENTAL (`kittest/suites.go`, `kittest/driver.go`). The suite, its
  driver observations and the variant set may change in any v0 release.

## Known gaps and follow-ups

- The allocation ceiling in `mcpstrict`'s `FuzzCheck` covers `Spec{}`
  only. Typed and Open specs are bounded only by the fixed-shape unit
  tests.
- `authn.Config.MinSecretBytes` stays 0 until dns's enforcing minor
  release lands (the Q8 timeline in the README option ledger).
- Release gate:
  - Three Markdown edge cases are accepted: an indented fence closer;
    `#vX`, HTML-comment and indented headings; and a fenced `## vX` line in
    `CHANGELOG.md`.
  - There is no tag ruleset yet. The gate reports a bad tag after the
    push; it does not stop the push.

## Release gate

The tag push runs CI (`.github/workflows/ci.yml`) and the release workflow
(`.github/workflows/release.yml`). The gate requires the tag push's own CI
run to have `go vet`, `go test -race ./...`, `fuzz smoke`, `govulncheck`
and `replace/go.work check` green, this file, and a `## v0.1.0` line in
`CHANGELOG.md`. Nothing is published: no image, binary or GitHub Release.
`release.yml` passes the tag and its peeled commit to
`release-gate -require-ci` as `-tag` and `-sha`, because GitHub ignores
step-env overrides of `GITHUB_SHA`, `GITHUB_REF` and `GITHUB_REF_NAME`.
A `workflow_dispatch` re-gate may be started from a branch, and the CI run
it matches is still the tag push's own run. `-tag` without `-sha`
skips the SHA cross-check.
